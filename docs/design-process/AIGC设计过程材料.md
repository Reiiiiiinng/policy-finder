## 一、方案探索：两个真实存在过的界面方案

### 方案 A · 等权卡片流（2026-09，`2e939d7` 之前）

结果页把所有命中项按引擎 tier 分成「强相关 / 可能相关 / 待确认」三段，**每条卡片结构完全一致**：
名称 + 元信息 + 两个并排药丸（可能相关 / ✓ 已核验）+ 「为什么推荐」全量理由（实测 3–4 条）
+ 「还需确认」2 条（每条带「为什么需要确认」）+ 「政策来源」4 行 + 证据链按钮 + 详情入口。

- **它解决了什么**：信息完整，用户能一次看到全部判断依据，适合"愿意逐条读完"的场景。
- **真实截图**：`.ui-shots/v2/s-results.png`（本轮已核对，单卡 4 条理由 + 2 条待确认 + 4 行来源，一屏装不下 1 张卡）。
- **暴露的问题**：一屏只放得下 1 张卡，用户要先读完 4 条理由才看到"下一步做什么"；
  且两个药丸并排导致「已核验」被误读为"已符合资格"。

### 方案 B · 分区式主卡（2026-10，`4c1978f`「第九阶段 v6 分区式主卡」，仅在 `theme-cb` 分支）

首条强相关升级为 `article.result-card.is-lead`：深青绿渐变底、白色标题、分类 SVG 图标、
「看看为什么推荐 / 看怎么办理」主次双按钮，证据链走内联展开（`data-lead-why` / `data-lead-detail`）。

- **它解决了什么**：首屏有明确视觉焦点与两个动作，解决了"信息全但不知道先看哪个"。
- **真实产物**：`origin/theme-cb` 上的 `frontend/assets/app.js`（+111/−13 行）、`frontend/assets/style.css`（+655 行）、
  `frontend/assets/skins.css`（+608 行），以及 `docs/v6-migration-report-20261010.md` 的实测记录。
  关键实现：`<article class="result-card is-lead">`、`<span class="lead-ic">${catSvgIcon(r.category)}</span>`、
  `<button class="lead-btn is-primary" data-lead-why="...">看看为什么推荐</button>`、
  `<a class="lead-btn is-secondary" data-lead-detail="...">看怎么办理</a>`。
- **暴露的问题**（同报告第 3 节原文）：`skins.css` 在 `style.css` 之后加载，默认皮肤 C 的「头条卡」规则
  特异性 (0,4,1) 把主卡盖成米白底，而主卡文字是白色 → **白底白字不可读**；首次修复特异性算成 (0,4,1) 仍打平告负，
  第二次加 `.tier-block` 前缀（(0,5,1)）才生效。

### 为什么最终没有把方案 B 合进 `partner-v1.1`

不是审美取舍，是**代价**：方案 B 依赖 `skins.css` / `skin-switcher.js` 两层皮肤机制，
一条主卡规则要跨 3 个样式文件用特异性打架才能稳定（上面那个白底白字就是打架打输的结果）。
在只有 5 个页面、单人维护、且要求 8 套测试全绿的前提下，引入皮肤层的长期维护成本高于收益。

**最终采用的第三条路（本轮 P6）**：不引入皮肤层，也不回到等权卡片流，而是把方案 A 的卡片
**按信息优先级重排**——首屏只留「是什么 / 为什么（一条）/ 下一步」，
把「其余理由」「还需确认 + 政策来源」做成可展开的二级信息。

> 注：`is-lead` 主卡形态只存在于 `origin/theme-cb`，`partner-v1.1` 上没有（已用 `grep` 确认，
> 当前分支只匹配到无关的 `.basis-lead`）。所以这不是"把 B 改掉"，而是**在 A 的基础上重排**。

> 三方案对比结论：A 的信息完整度最高但首屏效率最低；B 的首屏效率最高但引入皮肤层耦合；
> C（本轮）在不新增机制的前提下拿到 B 的首屏效率，代价是需要重新设计"折叠后信息不丢失"的验收口径。

**改动前后真实截图**：
- 改动前（方案 A 实况）：`.ui-shots/v2/s-results.png`
- 改动后（方案 C 实况）：`docs/design-process/card-after-v6.png`

## 二、视觉探索：AI 初稿与人工优化

> 本机**没有** `submission-assets/AI生成素材/` 目录（已确认：仓库与桌面均无该路径），
> 因此这一节只记录**本轮真实发生过**的视觉探索，不引用不存在的初稿文件。

### 视觉母题「一线」的三次迭代（真实过程）

目标（提示词包 P5）：给产品一个原创视觉符号，主题是「从生活情况发现权益」。

| 轮次 | AI 给出的方案 | 落地位置 | 人工判断 | 结果 |
| --- | --- | --- | --- | --- |
| 1 | 在结果卡里画 `生活线索 ┈▸ 政策名` | 每张结果卡顶部 | **否**：卡片标题已经是政策名，同一行里再画一遍是重复；且窄屏下政策名被截成「社区养...」 | 移除，`result-thread` 相关代码与 CSS 全删 |
| 2 | 把生活线索 chip 里的「关联 N 项权益方向」改成母题 | 场景 chip 内 | **否**：chip 自带 `sc-name`，母题两端都是 chip 内部已有的字，画线等于把一句话拆成两半 | 还原为纯文字 |
| 3 | `□ 生活线索 ┈▸ ● 权益名`，用在首页首屏 / 详情页首块 / 证据链顶部 | 3 个界面 | **是**：这三处的共同点是「用户没看到的对应关系」——首页是产品自述，详情页是"这条从哪来"，证据链是"凭什么推荐" | 保留，成为产品视觉母题 |

**人工介入的具体动作**（可核查）：
1. 第 1 轮和第 2 轮都是 AI 先实现、人工看真实截图后否决的，不是事后叙述。
2. 第 3 轮追加了**降级规则**：任一端为空就退回纯文字，不画半条线（`renderThread` 里的 `if (!c || !r)` 分支）。
   这条规则不是 AI 主动想到的，是人工在"数据可能只有一端"时补的防御。
3. 形状语义由人工定义并写进代码注释：起点空心方块 = 用户给的生活线索（未核对），
   虚线 = 推断段，终点实心圆 = 找到的权益。三个形状各自承载一个含义，不是装饰。

### 视觉规格（可复现）

```css
.th-clue::before  { width:6px; height:6px; border:1px solid var(--brand-mid); border-radius:1px; }  /* 起点：空心方 */
.th-path          { width:14px; height:0; border-top:1.5px dashed var(--brand-line); }             /* 中段：虚线 */
.th-right::before { width:6px; height:6px; border-radius:50%; background:var(--brand); }            /* 终点：实心圆 */
```

全部用 CSS 绘制，**无外链图片、无字体图标**（`page-check.js` 有对应断言）。

## 三、人工介入的具体动作汇总（本轮全部可核查）

| # | AI 产出的缺陷 | 人工判断过程 | 采取的手段 | 最终结果 |
| --- | --- | --- | --- | --- |
| 1 | 把 `missingHtml` / `sourceBlock(r)` 收进模板外变量，导致 `phase6-test.js` 的顺序断言取不到这两个字面量 | 读测试源码发现 `tpl` 从 `return \`` 起截取，变量在模板外就不在断言范围内 | 改回模板内联 | 顺序断言恢复，8 套绿 |
| 2 | 在代码注释里写了「查看更多 / 加载更多」解释折叠逻辑 | `phase6-test.js` 的禁用词正则扫的是**整个函数体含注释** | 换措辞为「另外 N 条理由」 | 通过 |
| 3 | P2 的 page-check 断言里用了 `read()` | 该文件没有 `read()` 函数（只有 `fs`） | 改用 `fs.readFileSync(path.join(ROOT, ...))` | 通过 |
| 4 | P1 的「出门前清单」初版把「建议携带 / 建议问清」既放在 `.where-row` 又放进 `.trip-list` | 看真实截图发现同一页出现两遍同样内容 | 删掉两行 `.where-row`，内容只留 trip-list | 无重复 |
| 5 | 触达面积用 `::after` 伪元素撑开（`.reason-more` / `.fs-clear`） | 实测 `getBoundingClientRect().height` 仍是 27px / 22px，伪元素不改盒高，验收量不到 | 改为 `display:inline-flex; min-height:48px` 撑真实盒高 | 实测 48px |
| 6 | 母题在结果卡里重复标题（见上表第 1 轮） | 真实截图否决 | 整体移除 | 已删 |
