# V3.4 产品能力差距审查

| 审查项 | V3.3 的真实逻辑 | V3.4 处理及缺口 |
| --- | --- | --- |
| 家庭事实 | `household_analysis.intake` 调用提取、需求推断两阶段。年龄和居住城市由 `base_facts` 基于录入值和文本规则解析，矛盾进入核对。仅在城市匹配时采信明确的户籍、参保自述。 | 推荐详情显示条件事实来源。原始描述、AI 提取和需求推断在「查看或修改 AI 理解的信息」保留。佛山区或街道仍无独立结构化字段。 |
| 推荐 | `vetted` 先按目录、效力和规则筛除，`rank` 只允许 AI 返回目录 ID 和理由，规则回退使用场景匹配。 | 新增佛山养老消费补贴和突发生活困难场景。核对医疗救助原文后修正未参保硬排除。 |
| 条件存储 | JSON 的 qualify、thresholds、result_params 与旧式字段并行，证据链走 `build_evidence_chain`。 | 补充单项符合、不符合、信息未明、官方认定、依据待核实状态，参保这类经办信息有独立文案。 |
| 用户回答 | `questions` 按目录生成户籍、医保、失能、困难类别和定点机构相关问题。已有事实跳过，部分资料可重算。 | 继续复用集中核对和计划内条件。缺少年龄时可进入计划并继续补充。旧查询同步规则仍沿用原逻辑。 |
| 官方认定 | `_condition_input` 区分事实、官方结果、观察和参考。集中核对可填正式结果来源，但 V3.3 的部分规则标签表意过强。 | 推荐和计划区分用户转述与需要官方认定。计划录入仍是用户记录，当前无官方结果凭证接口。 |
| 文件与时效 | `source`、`validity`、`verification` 各自有职责。当前有效性派生与历史快照分开。 | 新条目随文件记录文号、范围、期限和核验依据。已过期、已被替代条目继续从当前推荐排除。 |
| 办理渠道 | `action_plan._project` 从流程文本抽取地点。发布机关可能被理解为受理窗口。 | 新增带来源、层级、地域和角色的 channels，推荐详情、完成页、计划及咨询共用。具体区街电话与地址覆盖有限。 |
| 下一步 | `_next_task_action` 按条件、材料、已提交进度生成计划内动作。推荐卡主要展示理由和待核实。 | 推荐和完成页补上首要动作。集中核对结果进计划，单项条件未知可继续处理其他事项。 |
| 官方咨询 | `consultationText` 读取原任务未解决条件，咨询命令按计划、任务、事项和成员归档。 | 增加同源渠道展示，已解决的条件继续从咨询问题中过滤。 |
| 联网 | `/api/search/web` → `SearchService.search` → CleverSee 真实适配器。实例开关默认关闭，预览还可注入模拟传输。 | 继续使用现有服务。提供公开关键词、已核验目录匹配、官方线索和第三方分类。查询须由用户发起。 |

操作范围为独立 Git 检出。原 V3.3 验收目录只新增本交付文件夹。
